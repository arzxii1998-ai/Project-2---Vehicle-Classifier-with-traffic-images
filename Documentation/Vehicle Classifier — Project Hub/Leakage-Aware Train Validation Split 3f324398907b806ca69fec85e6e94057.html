Near-duplicate frames were grouped before splitting, so the validation set never contains a vehicle the model has already seen.

What we did. Instead of splitting the training pool randomly image by image, we split it by groups of visually similar images. Every image was assigned a group_id, and all images that share a group were placed together, either all in train or all in validation. The final manifest (train_val_split_Manifest.csv) stores this as path, class, filename, group_id, split.

Why. While inspecting the data we saw that the same vehicle often appears in two or more frames captured moments apart, with only a small shift in position. Exact-duplicate removal does not catch these pairs, because their perceptual-hash similarity can be as low as 0.7–0.85. With a random split, one frame of a vehicle could land in train and its twin in validation. The model would then be tested on something it has effectively already seen, and validation metrics would be optimistically biased. Since every model choice (best epoch, ablations, scheduler, review threshold) is based on validation, this bias would have affected the whole project, so we treated it as a leakage problem and prevented it at the source.

How. We computed a 256-bit perceptual hash (pHash, 16×16) for every image and linked any two images whose similarity was at least 0.82. A Union-Find structure then merged these links into connected components, and each component became one group_id, so chains of similar frames (A~B, B~C) end up in the same group. We chose a threshold slightly below the 0.85 level of the shifted-frame pairs on purpose: wrongly merging two look-alike vehicles only makes the split a little less balanced, while missing a true pair would leak data. The split itself uses StratifiedGroupKFold (5 folds, one fold taken as validation, seed 42), which keeps groups intact and keeps class proportions close to equal in both parts. The pHash column is used only internally and is not stored in the final manifest.

Verification and reproducibility. After the split, validate_split asserts that no image path and no group_id appears in both train and validation, and that there are no duplicate paths. We also checked the group-size distribution and the class-by-split counts. The seed, number of folds, similarity threshold, and class counts are saved in configs/split_config.json, which is tracked in Git, and the manifest is the single source for every later experiment. As a result, all runs share exactly the same split, and the validation scores we report are an honest estimate of performance on unseen vehicles rather than on near-copies of training images.
