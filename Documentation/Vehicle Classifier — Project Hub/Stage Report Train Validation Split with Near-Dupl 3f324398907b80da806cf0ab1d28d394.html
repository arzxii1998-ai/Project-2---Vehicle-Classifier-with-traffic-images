Stage Report: Train/Validation Split with Near-Duplicate Grouping

1. Problem

The cleaned dataset provided a train pool (818 images, 8 classes) and a frozen test set (397 images), but no validation split. A naive random split was not safe to use: the dataset contains near-duplicate images (e.g., consecutive frames of the same vehicle), and a random split could

place near-duplicates of the same vehicle in both train and validation, producing an artificially optimistic validation score (data leakage).

2. Goal

Produce a train/validation split from the 818-image train pool that:

  • Keeps near-duplicate images together in a single split (never splitacross train and validation).
  • Preserves each class's proportion in both splits (stratification),which matters most for the smallest class (kamyun, 65 images).
  • Is fully reproducible (fixed seed, logged parameters).
  • Leaves the test set and the cleaned image folders untouched.

3. Approach

  1. Image table (load_image_DF) — scanned dataset/CombinedDataset/train and built a DataFrame with one row per image(path, class, filename), using paths relative to the projectroot for OS-independence.
  1. Near-duplicate grouping (hash_image_df + assign_group_ids) —computed a perceptual hash (pHash) per image, then reused theexisting Union-Find clustering logic fromduplicate_detection.py (_to_bit_matrix, _find_similar_pairs,_cluster_images) to assign a group_id to every image. Groupingis transitive: if A~B and B~C, all three land in one group even ifA and C were never compared directly above the threshold.Similarity threshold: 0.82.
  1. Stratified group split (split_train_val) — usedsklearn.model_selection.StratifiedGroupKFold (n_splits=5,shuffle=True, random_state=42), taking a single fold asvalidation (~20%). This guarantees, by construction, that nogroup_id is split across train and validation, while keepingclass proportions close to even.
  1. Validation checks (validate_split) — automated assertions:no image path in both splits, no group_id in both splits, noduplicate paths in the manifest.
  1. Group-size sanity check — inspected the distribution of groupsizes to confirm no single oversized cluster could distort thestratification.
  1. Outputs saved:
    • data/grouped_train_pool.csv — full image table with group_id.
    • data/train_val_split.csv — final manifest with the splitscolumn (train / val).
    • configs/split_config.json — seed, n_splits, similaritythreshold, and per-class counts (kept in configs/, not data/,since it records a decision rather than a reproducibleintermediate artifact).

4. Verification

  • validate_split passed: no shared paths, no shared group_idvalues, no duplicate rows.
  • split["splits"].value_counts() confirmed an ~80/20 total split.
  • pd.crosstab(class, splits, normalize="index") confirmed each ofthe 8 classes kept a roughly 80/20 proportion between train andvalidation.
  • Group-size distribution reviewed manually; no cluster large enoughto distort stratification.

5. Output

  • Final split: ~654 train / ~164 validation images, out of 818,grouped and stratified across 8 classes.
  • Deliverables: src/vehicle_classifier/splitting.py(load_image_DF, hash_image_df, assign_group_ids,split_train_val, validate_split, save_the_df_CSV,save_split_config), plus the two CSV manifests and one JSON configfile described above.
  • Status: complete. Ready for the next stage — building the PyTorchDataset/DataLoader pipeline from data/train_val_split.csv.
