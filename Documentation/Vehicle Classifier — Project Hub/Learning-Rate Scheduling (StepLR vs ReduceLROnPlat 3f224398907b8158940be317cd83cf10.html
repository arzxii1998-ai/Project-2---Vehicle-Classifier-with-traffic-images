Learning-Rate Scheduling (StepLR vs. ReduceLROnPlateau)

Learning-rate scheduling improved CNN performance, with ReduceLROnPlateau achieving the best results; however, its modest advantage over StepLR remains tentative due to the single-seed evaluation and limited training budget.

Setup. We compare a fixed learning rate against two schedulers, all using AdamW with an initial learning rate of 1e-3 and CE loss on a single seed (42). The comparisons are paired so that only the scheduler differs:

  • StepLR: the learning rate is multiplied by <gamma> every <step_size> epochs, regardless of validation performance.
  • ReduceLROnPlateau: the learning rate is multiplied by <factor> when validation loss has not improved for <patience> epochs. scheduler.step(val_loss) is called after validation, so test data never influences the schedule.

Result. Adding StepLR to the 4-block CNN improved accuracy by 1.30 pp (10 validation images) and macro-F1 by 1.10 pp, and lowered validation loss from 0.525 to 0.454. On the 5-block CNN, replacing StepLR with ReduceLROnPlateau improved accuracy by 0.78 pp (6 images) and macro-F1 by 0.78 pp, with the lowest validation loss among the CE CNN runs (0.167). The lowest-recall class was kamyun in both runs.

Interpretation. Lowering the learning rate late in training lets the model settle near a good solution instead of oscillating around it. ReduceLROnPlateau reduces the rate only when validation loss stalls, whereas StepLR follows a fixed schedule that cannot adapt to the actual progress of training. This is a plausible reason for the small advantage of plateau. It was not tested directly, but the per-epoch learning rates logged for each run can be used to check when each scheduler actually reduced the rate. Notably, the plateau run reached its best epoch at the last epoch (50 of 50), so it was still improving when the training budget ended.

Caveats. All results come from a single seed, and the plateau-vs-step gap (6 images) is small enough to be partly run-to-run variation. A BCE pair (full_ablation_bce vs. full_ablation_bce_plateau_decoy) also switches to plateau, but it changes weight decay at the same time and gave identical accuracy (94.81%), so it is not a clean test and is excluded here. The comparison depth5 (no scheduler, 30 epochs) vs. full_ablation (StepLR, 50 epochs) changes the training budget as well, so it is also excluded.
